# Benchmark workflow sources

Files: Pegasus DAX 2.1 benchmark workflows generated by the Pegasus Workflow Generator, distributed with WorkflowSim-1.0
(https://github.com/WorkflowSim/WorkflowSim-1.0/tree/master/config/dax). Downloaded with `scripts/download_benchmarks.py`, which verifies the SHA-256 below.

Cite: Bharathi, S., Chervenak, A., Deelman, E., Mehta, G., Su, M.-H., & Vahi, K. (2008). Characterization of scientific workflows. 2008 Third Workshop on Workflows in Support of Large-Scale Science, 1–10. https://doi.org/10.1109/WORKS.2008.4723958
Juve, G., Chervenak, A., Deelman, E., Bharathi, S., Mehta, G., & Vahi, K. (2013). Characterizing and profiling scientific workflows. Future Generation Computer Systems, 29(3), 682–692. https://doi.org/10.1016/j.future.2012.08.015
Chen, W., & Deelman, E. (2012). WorkflowSim: A toolkit for simulating scientific workflows in distributed environments. 2012 IEEE 8th International Conference on E-Science, 1–8. https://doi.org/10.1109/eScience.2012.6404430

How they are used: the file whose task count is closest to `workflow_size` is loaded (`fgrl.workflows.generator.load_dax`); task runtimes (seconds) are converted to work by multiplying with the Tier 2 reference speed, and the data volume of an edge is the total size of the files the parent writes and the child reads. Training, validation and test instances are drawn with `trace_variant`: same topology and job types, runtimes and file sizes bootstrap-resampled within each job type plus 10 % log-normal jitter, with disjoint random seeds. The unmodified benchmark file is always one of the test instances.
